01Resumen y palabras clave

Este trabajo describe el software de aplicación y su papel en la gestión del talento humano. Parte del Reto 3 de la guía «Retos del planeta Byteon», que define el software de aplicación como el programa que ayuda al usuario a realizar tareas específicas, y presenta sus tipos, el sistema de versiones X.Y.Z y la clasificación por estabilidad (alfa, beta y candidata a lanzamiento). Se amplía con la ubicación del software de aplicación frente al de sistema y al de programación, las formas de entrega (escritorio, web, móvil y nube), los modelos de licencia, el versionado semántico y los ciclos de soporte, el modelo de calidad ISO/IEC 25010 y los criterios para elegir una aplicación, incluidos el costo total de propiedad y una matriz ponderada. Se relaciona con la normativa colombiana de derechos de autor, datos personales y nómina electrónica. Se concluye que elegir y mantener una aplicación es una decisión de gestión que equilibra funcionalidad, seguridad, costo, soporte y cumplimiento legal.

Palabras clave: software de aplicación, tipos de software, versionado, licencias, SaaS, calidad de software, costo total de propiedad, talento humano.

02Introducción

Casi todo proceso de talento humano pasa hoy por una aplicación: la hoja de cálculo del ausentismo, la plataforma de selección, el sistema de nómina, el curso virtual de inducción. El software de aplicación es el programa diseñado para que el usuario realice tareas específicas; se distingue del software de sistema, que administra los recursos del equipo y ofrece servicios básicos a otros programas (Sommerville, 2016; Tanenbaum y Bos, 2015). La guía de Byteon presenta el tema como un recorrido por el núcleo prohibido; este documento lo desarrolla con fuentes reales y lo traduce al trabajo del técnico en talento humano.

03Planteamiento del problema y justificación

En muchas áreas de personas se usan aplicaciones sin criterio: programas descargados sin licencia, versiones beta con datos reales, sistemas sin soporte que ya no reciben actualizaciones de seguridad, herramientas gratuitas que guardan datos en otros países y múltiples aplicaciones que no se comunican entre sí. Un ejemplo reciente es el fin del soporte de Windows 10 el 14 de octubre de 2025: los equipos que lo siguen usando dejan de recibir actualizaciones de seguridad gratuitas.

Pregunta de investigación: ¿qué tipos de software de aplicación existen, cómo se identifican sus versiones y con qué criterios se debe elegir y usar una aplicación en un área de talento humano?

Justificación: el técnico debe operar herramientas digitales, comparar opciones, interpretar versiones y cuidar licencias y datos personales. Esa competencia reduce costos, evita sanciones y mejora la calidad del servicio al empleado.

06Marco teórico

6.1 Definición y ubicación

El software son los programas, procedimientos y datos asociados que hacen funcionar un sistema informático (ISO/IEC/IEEE 24765:2017). Se organiza en capas que van del hardware al usuario.

TipoFunciónEjemplos
Software de sistemaGestiona el hardware y presta servicios a otros programasWindows, Linux, macOS, Android; controladores; utilidades
Software de programaciónPermite crear otros programasCompiladores, editores de código, entornos de desarrollo (IDE)
Software de aplicaciónAyuda al usuario a realizar tareas específicasHojas de cálculo, sistemas de nómina, correo, plataformas de aprendizaje

La frontera no siempre es nítida: la guía de Byteon incluye entornos de desarrollo y herramientas de seguridad entre los usos del software de aplicación, y muchas taxonomías los consideran software de programación o de seguridad especializados. Además existen el firmware (programa en el dispositivo) y el middleware (capa que conecta aplicaciones).

6.3 Formas de entrega y de licencia

CriterioOpcionesObservaciones
EntregaDe escritorio (instalada), web, móvil (nativa o híbrida), en la nubeLa web y la nube evitan instalar, pero dependen de la conexión
Modelo de nubeSaaS, PaaS, IaaS (NIST SP 800-145)La mayoría de las aplicaciones de talento humano modernas son SaaS
LicenciaPropietaria; software libre o de código abierto (GPL, MIT, Apache); freeware; shareware; suscripciónLa licencia da un derecho de uso, no la propiedad

El software libre se define por cuatro libertades: ejecutar, estudiar y adaptar, redistribuir y distribuir copias modificadas (Free Software Foundation). El código abierto se define por diez criterios de la Open Source Initiative. «Libre» no significa necesariamente gratuito, ni «gratuito» significa libre: un programa freeware puede prohibir modificar su código.

6.4 Versiones

La versión identifica un estado del programa y permite saber qué cambió. La guía presenta el esquema X.Y.Z. La especificación de versionado semántico (SemVer 2.0.0) lo precisa así:

NúmeroNombreCuándo aumentaEjemplo
XMayor (MAJOR)Cambios incompatibles con versiones anteriores4.3.1 → 5.0.0
YMenor (MINOR)Funciones nuevas compatibles4.3.1 → 4.4.0
ZParche o revisión (PATCH)Corrección de errores compatibles4.3.1 → 4.3.2

Etapas de estabilidad: alfa (pruebas internas, incompleta e inestable), beta (pruebas con usuarios externos, más completa pero con errores), candidata a lanzamiento (RC) (posible versión final si no aparecen fallas graves) y disponibilidad general (GA). En SemVer, las preversiones se ordenan así: 2.0.0-alpha < 2.0.0-beta < 2.0.0-rc.1 < 2.0.0. Algunas versiones de largo soporte se rotulan LTS. No todos los productos usan SemVer: Ubuntu usa año y mes (24.04 LTS), muchos navegadores usan números enteros de lanzamiento rápido y las suites en suscripción se actualizan de forma continua.

Ciclo de soporte: cada versión tiene un periodo de soporte; al terminar (fin de vida, EOL), el fabricante deja de entregar parches y la organización queda expuesta. Por eso se lleva un inventario de software con sus versiones (ISO/IEC 19770-1).

6.5 Calidad del software: ISO/IEC 25010

El modelo de calidad del producto de ISO/IEC 25010:2011 define ocho características: adecuación funcional, eficiencia de desempeño, compatibilidad, usabilidad, fiabilidad, seguridad, mantenibilidad y portabilidad. La edición de 2023 la actualiza y añade la seguridad operacional (safety). Sirven como lista de verificación para evaluar una aplicación antes de adoptarla.

6.6 Selección y costo total de propiedad

  • Requisitos: funcionales (qué debe hacer) y no funcionales (seguridad, rendimiento, accesibilidad, integración).
  • Interoperabilidad: formatos abiertos como ODF (ISO/IEC 26300), OOXML (ISO/IEC 29500), PDF (ISO 32000) y CSV, e interfaces (API) para intercambiar datos.
  • Accesibilidad: pautas WCAG 2.2 del W3C.
  • Proveedor: soporte, hoja de ruta, estabilidad y condiciones del contrato.
  • Costo total de propiedad (TCO): licencias o suscripciones, implementación, capacitación, soporte, infraestructura, migración y salida, no solo el precio de compra.
  • Matriz ponderada: se asigna un peso a cada criterio y una calificación a cada opción; el puntaje es la suma de peso × calificación.

6.7 Ciclo de adopción

Necesidad → requisitos → evaluación y comparación → prueba piloto con datos de prueba → contrato y licencia → implementación y capacitación → operación, copias y actualizaciones → retiro y migración de datos.

Buena práctica: antes de cargar datos reales de personas en una aplicación nueva, verifique la licencia, la versión estable (evite alfa y beta), el contrato con el proveedor como encargado de datos, la ubicación de los servidores y las medidas de seguridad (cifrado, MFA, registros).

08Marco normativo y estándares

  • Derechos de autor: Ley 23 de 1982 (modificada por la Ley 1915 de 2018), Ley 44 de 1993 y Decisión Andina 351 de 1993; el software se protege como obra. Ley 603 de 2000: las sociedades comerciales deben informar en su informe de gestión el cumplimiento de las normas sobre propiedad intelectual y derechos de autor. La Dirección Nacional de Derecho de Autor (DNDA) vigila el cumplimiento.
  • Ley 1273 de 2009: delitos informáticos; Ley 1581 de 2012 y Decreto 1074 de 2015: las aplicaciones que tratan datos personales deben respetar autorización, finalidad y seguridad; el proveedor suele actuar como encargado del tratamiento y las transferencias internacionales tienen condiciones (art. 26).
  • Ley 527 de 1999 y Decreto 2364 de 2012: validez de mensajes de datos y firma electrónica.
  • Nómina electrónica: Resolución 000013 de 2021 de la DIAN, que establece el documento soporte de pago de nómina electrónica; el software de nómina debe generarlo. Verifique la vigencia.
  • Accesibilidad: Resolución 1519 de 2020 de MinTIC para sujetos obligados (entidades públicas) y WCAG 2.2.
  • Estándares: ISO/IEC/IEEE 24765 (vocabulario), ISO/IEC 12207 (ciclo de vida), ISO/IEC 25010 (calidad), ISO/IEC 19770-1 (gestión de activos de software), ISO/IEC 27001 (seguridad de la información) y NIST SP 800-145 (nube).

10Tendencias y retos

  • Predominio del SaaS: menos instalación y más actualización continua, pero con dependencia del proveedor y de la conexión.
  • Inteligencia artificial integrada: asistentes y analítica en las aplicaciones. El Reglamento (UE) 2024/1689 clasifica como de alto riesgo los sistemas de IA usados en selección y gestión de trabajadores; en Colombia, el CONPES 4144 de 2025 define la política nacional de IA.
  • Automatización y bajo código: flujos con poco programa (RPA, plataformas de bajo código) que agilizan trámites.
  • Autoservicio del empleado y apps móviles para certificados, vacaciones y desprendibles.
  • Interoperabilidad por API y reducción de aplicaciones aisladas (silos de datos).
  • Software no autorizado (shadow IT) y fin de soporte de versiones antiguas como riesgos de seguridad y de cumplimiento.

11Conclusiones

  1. El software de aplicación sirve para tareas específicas del usuario y se distingue del software de sistema y del de programación, aunque las fronteras a veces se solapan.
  2. Las aplicaciones se clasifican por función, forma de entrega y licencia; en talento humano predominan las de gestión empresarial, educativas y de productividad en la nube.
  3. La versión comunica qué cambió y qué tan estable es; las versiones alfa y beta no son aptas para datos reales.
  4. Elegir una aplicación exige evaluar calidad, interoperabilidad, soporte y costo total, no solo el precio.
  5. La licencia, los datos personales y la nómina electrónica convierten la elección del software en una obligación legal.

12Recomendaciones

  • Mantener un inventario de aplicaciones con versión, licencia, responsable y fecha de fin de soporte.
  • Comparar siempre al menos dos opciones con una matriz ponderada y el costo total a tres años.
  • Probar con datos ficticios y en una versión estable antes de cargar datos reales.
  • Verificar contrato, ubicación de los datos y medidas de seguridad del proveedor.
  • Aplicar parches y retirar o aislar las versiones sin soporte.
  • Capacitar a los usuarios y documentar con manuales actualizados.

13Glosario

  • API: interfaz que permite que dos aplicaciones intercambien datos.
  • ATS: sistema de seguimiento de candidatos.
  • EOL: fin de vida; el fabricante ya no da soporte.
  • HRIS: sistema de información de recursos humanos.
  • LMS: plataforma de gestión del aprendizaje.
  • Parche: actualización que corrige errores o vulnerabilidades.
  • SaaS: software como servicio, en la nube y por suscripción.
  • SemVer: versionado semántico (mayor.menor.parche).
  • TCO: costo total de propiedad.
